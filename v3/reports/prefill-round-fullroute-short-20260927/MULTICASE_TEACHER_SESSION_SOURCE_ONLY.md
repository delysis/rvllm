# Multi-case teacher session: source-only research path

The feature-gated `rvllm_metal_infer --prompts-jsonl PATH --teacher-session --json` path uses the existing direct Metal session backend. It prepares one model backend and processes one to four named cases sequentially, with a fresh request ID per case. Each line is strict JSON with `name`, `prompt`, `max_new_tokens` (1–64), and an equally long `teacher_token_ids` array; optional `max_total_tokens` and `no_bos` are per-case. Duplicate JSON keys, unknown fields, blank lines, duplicate names, missing targets, and mixed reference/profile/EOS/other teacher-probe modes fail closed. Targets must fit the model vocabulary before backend preparation.

Each decode step follows the normal rollout route, captures the sampled token and logits, scores the supplied target, and feeds that target into the next step. The case report keeps forced `generated_token_ids` separate from `teacher_forced.steps[].sampled_token_id`. The separate `rvllm.metal_teacher_forced_session.v1` report omits timing values, marks `timing_valid: false`, and retains dispatch counters. This is not a speed or independent quality result.
