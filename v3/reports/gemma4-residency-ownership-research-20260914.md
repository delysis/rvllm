# Gemma 4 12B: source ownership and lower residency

Source-only review, 2026-09-14. No selectors, hardware workloads, builds, process changes, or cache access. The parent reports all 162 cached FP16 programs loaded and one complete decode matching all 48 baseline layer states byte-for-byte. The approximately 12 GB disk decline and 13,030 MB swap usage motivate this review; they do not identify which allocation was swapped or prove a leak.

**Recommended first change: finish every qualification prefill, retain the owned prompt starts, release the idle Metal backend, then load ANE once and decode those starts.** This removes a model-sized allocation without altering ANE descriptors or cache identities. The next allocation improvement is ownership transfer into `NSData`, which saves a transient copy. I found no primary implementation demonstrating safe removal of descriptor-owned source weights while preserving a loaded `_ANEInMemoryModel` through evaluation, unload, and cache reuse.

## The ownership boundary we can establish

The current [ANE constructor](/Users/george/Downloads/rvllm/v3/crates/rvllm-apple-ane-sys/src/in_memory.rs:290) creates `NSData::with_bytes(weights)`, inserts it into nested dictionaries, creates a descriptor and model, then compiles/loads. The local descriptor drops before compilation; the data/dictionary references drop when construction returns, and the per-program autorelease pool drains. [LoadedProgram](/Users/george/Downloads/rvllm/v3/crates/rvllm-apple-ane-sys/src/in_memory.rs:146) retains the model, options and directory, not a Rust weight buffer. [GemmaAneDecode](/Users/george/Downloads/rvllm/v3/crates/rvllm-runtime/src/gemma_ane_decode.rs:272) explicitly drops QKV, O and FFN source vectors after each program is constructed. Therefore an additional `drop` of those existing local references cannot remove model-owned storage.

Foundation collections [retain their contents](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/MemoryMgmt/Articles/mmPractical.html#//apple_ref/doc/uid/20000043-SW1). The installed objc2-foundation 0.3.2 [implementation](https://github.com/madsmtm/objc2/blob/7b1abfd750a2cacaea71d6a56ecfb83cb7de560b/framework-crates/objc2-foundation/src/data.rs#L35) shows `with_bytes` calling copying `initWithBytes:length:`. These establish the application-side copy and collection ownership. They do **not** reveal whether this macOS private descriptor retains the same immutable data, copies it, or whether loading makes further private copies. The model/descriptor source-retention explanation is plausible and consistent with the API, but its exact retained-object graph has not been audited here.

The [tmc generated bindings](https://github.com/tmc/apple/blob/872b4b8c75cb24617d606e0484c1db1e2948f01e/private/appleneuralengine/ane_in_memory_model.gen.go#L320) expose `setDescriptor:`; the [descriptor binding](https://github.com/tmc/apple/blob/872b4b8c75cb24617d606e0484c1db1e2948f01e/private/appleneuralengine/ane_in_memory_model_descriptor.gen.go) exposes weights, network text and their hashes, without a demonstrated source-release operation. Generated selector availability is not an ownership contract or proof that setting the descriptor to nil preserves identity-dependent operations. Do not clear it, mutate its dictionary/data, or replace it with an empty descriptor on this evidence.

The actual upstream implementations inspected preserve the loaded model:

* [maderix/ANE bridge](https://github.com/maderix/ANE/blob/d91c9845c0784dec7753048954fc6d0e8411fe29/bridge/ane_bridge.m#L83) copies caller weights into NSData; its [cleanup](https://github.com/maderix/ANE/blob/d91c9845c0784dec7753048954fc6d0e8411fe29/bridge/ane_bridge.m#L250) unloads before releasing model ownership.
* [h3 bridge](https://github.com/maderix/h3.c-ane/blob/6538b226efe5c4fff905d299dcc4426db2f44de4/h3_ane_bridge.m#L154) transfers a malloc-owned blob into `dataWithBytesNoCopy:length:freeWhenDone:YES`, retains the model/request, and subsequently unloads during destruction. It does not demonstrate releasing the descriptor's source after load.
* [skyfallsin/ane.cpp](https://github.com/skyfallsin/ane.cpp/blob/b87bf57356c26025853a60cddfe4b58784ee4fda/core/ane_runtime.cpp#L1875) reads a blob into malloc memory and transfers ownership with the same no-copy constructor; its [loaded kernel](https://github.com/skyfallsin/ane.cpp/blob/b87bf57356c26025853a60cddfe4b58784ee4fda/core/ane_runtime.cpp#L649) retains the model. Again, pool drainage releases local ownership, not necessarily the final weight owner.

## Metal retention: one shared model allocation, not separate CPU and GPU models

[MetalBufferArena](/Users/george/Downloads/rvllm/v3/crates/rvllm-apple-metal/src/arena.rs:29) owns one shared-storage MTLBuffer. A `MetalRegion` clone copies a name/offset/size descriptor, not weight bytes. The [loader](/Users/george/Downloads/rvllm/v3/crates/rvllm-apple-metal/src/weight_loader.rs:538) actually reads a tensor into a temporary Vec, copies it into the arena, then drops the Vec on that loop iteration; its module-level mmap description is stale. The [tied embedding/head](/Users/george/Downloads/rvllm/v3/crates/rvllm-apple-metal/src/gemma4_model.rs:2262) alias one region. Extra execution slots duplicate mutable scratch, while weights and KV pages remain shared.

The avoidable overlap is **Metal's model arena plus ANE model/source/runtime allocations**, not a second persistent CPU Vec belonging to Metal. The [qualification driver](/Users/george/Downloads/rvllm/v3/crates/rvllm-runtime/src/bin/rvllm_disaggregated_infer.rs:177) keeps `metal` alive across the entire case loop and loads ANE inside that loop. Consequently both model paths stay resident together. Removing the Metal owner can release roughly the 23.8 GB projection/head weight budget plus its scratch and other arena regions; use the existing `model_capacity()`/`probe_arena_stats()` values for the exact allocation, rather than that approximation.

The boundary already supports phase separation: [prefill_for_ane](/Users/george/Downloads/rvllm/v3/crates/rvllm-runtime/src/apple_metal_backend.rs:1971) collects the submitted command before exporting KV, and [AneDecodeStart/AnePrefillSnapshot](/Users/george/Downloads/rvllm/v3/crates/rvllm-runtime/src/ane_prefill.rs:24) own FP16 vectors, with no borrowed Metal pointers. Preserve first token, source dtype, numeric ABI, positions, and all case receipts; then drop the drained backend before ANE loading. Reuse the ANE decoder across the saved starts. This is a qualification/single-prefill lifetime improvement; a service promising overlapping new prefills must separately budget or reload its Metal model.

## Ranked follow-up and proof required

1. **Phase-separated ownership — high source confidence, unmeasured reclamation.** Record arena bytes and process footprint before/after idle Metal destruction and autorelease-pool drainage, then through ANE loading. Ensure no submitted Metal command or retained command-buffer owner survives. Confirm saved starts and resulting layer receipts are unchanged. Track *new* swap activity and peak footprint; free-memory percentage or residual swap after process exit cannot establish the live ownership graph.
2. **Move the owned blob into NSData — high API confidence, mainly transient savings.** Use the existing safe `NSData::from_vec(Vec<u8>)`, not a borrowed slice with `freeWhenDone:YES`. Its [deallocator](https://github.com/madsmtm/objc2/blob/7b1abfd750a2cacaea71d6a56ecfb83cb7de560b/framework-crates/objc2-foundation/src/data.rs#L305) captures Vec capacity and reconstructs/drops that exact allocation when Foundation releases it. Default dependency features already include `block2`/`alloc`. Have the builder transfer the blob once; preserve immutable byte access for staging verification inside the FFI crate. This can avoid approximately 354 MB of additional temporary copying for a full FFN, not 354 MB per already-loaded layer. Verify unchanged graph/cache identifiers, cached load, evaluation and ordinary unload on a small fixture before scaling.
3. **File-backed immutable NSData — lower confidence for this private path.** Foundation offers [mappedIfSafe](https://developer.apple.com/documentation/foundation/nsdata/readingoptions/mappedifsafe), but it is a mapping hint and the framework may copy again. This retains source bytes in a file rather than making them disappear; the converted FP16 blobs would require about another model-sized disk allocation if no suitable existing source is retained. Current source unlinking is incompatible with assuming named backing files remain reusable, and an unlinked open/mapped file can still occupy disk. With constrained disk, defer this until a small experiment proves identity, actual backing, reclaimability and no anonymous duplicate.

No source supports forcibly clearing descriptor data as the next step. Reducing the verified Metal/ANE lifetime overlap is the largest concrete change with the least private-API uncertainty; ownership-transfer construction then reduces peak load pressure without changing the loaded model lifecycle.
