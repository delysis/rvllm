# Source-path lifetime versus storage-pressure cache loss

2026-09-16. Source and saved-evidence review only. No ANE calls, compilation, live log fetch, cache/disk mutation, builds, or production changes were performed; this report is the sole write. Target remains macOS 15.6 / 24G84, ANE 8.600.2, one graph input/output.

**Updated assessment:** active CacheDelete handling is now directly observed on this laptop. Missing caller-source paths remain a plausible eligibility factor, but are not established as the cause. These mechanisms are not necessarily exclusive: source reachability could influence which entries a storage-maintenance pass selects. Preserve production cleanup and stop repeated full-model provisioning until repair survives a fresh strict load.

## Source evidence, with applicability limits

- **Public Core ML:** Apple says specialized assets can be deleted for low storage, OS updates, or deletion/modification of the compiled model. Here “compiled model” is the application's `.mlmodelc` resource that Core ML specializes. This does **not** say that removing rvllm's temporary `weights/weight.bin` or `data` has the same effect. [Apple WWDC23 session 10049, model lifecycle](https://developer.apple.com/videos/play/wwdc2023/10049/).
- **Private source tracking exists:** the extracted ANECompilerService interface includes a `saveSourceURL:` parameter and distinguishes `modelURL` from `sourceURL`. The extraction also includes `model.src`; the maintainer includes `model.retain` and `kANEFRetainModelsWithoutSourceURLKey`. These names support a source-tracking hypothesis but reveal neither the exact removal predicate nor a safe retention API. Pin `826027d4463eab23b96c4325fa7154ef43c75acd` compares **iOS 18.5 / 22F76 with iOS 26.0 beta / 23A5260n**, not macOS 24G84; old-side strings must not be presented as live behavior. [compiler extraction](https://github.com/blacktop/ipsw-diffs/blob/826027d4463eab23b96c4325fa7154ef43c75acd/18_5_22F76__vs_26_0_23A5260n/MACHOS/ANECompilerService.md), [maintainer symbol](https://github.com/blacktop/ipsw-diffs/blob/826027d4463eab23b96c4325fa7154ef43c75acd/18_5_22F76__vs_26_0_23A5260n/MACHOS/ANEStorageMaintainer.md#L280).

## The previous pair did not test post-exit retention

The [earlier report](/Users/george/Downloads/rvllm/v3/reports/gemma4-ane-cache-lifetime-research-20260915.md) accurately records both 30 MiB fixtures surviving 63.388 seconds. However, the [test:90–103](/Users/george/Downloads/rvllm/v3/crates/rvllm-apple-ane-sys/src/cache_lifetime_tests.rs:90) unloads, drops each program, and asserts its directory is absent. Thus both arms lacked paths during the delayed checks. The test compared cleanup **after load versus at unload**, not retained versus absent source paths during later maintenance. Repeating that same pair for longer would leave this distinction untested.

## One proposed bounded experiment

After headroom is restored and active recovery/build cleanup has stopped, use **two disposable copies of the same real-size baseline INT8 FFN graph**, with identical weights/options/one-I/O geometry and distinct diagnostic operation names. Freeze one executable/signing identity. This is a proposed test-harness change, not authorization to run it now.

1. Permit at most **two cold compiles, two initial loads, zero requests/evaluations**, with an explicit total disk-growth cap and predeclared disk floor. Never purge to manufacture a miss. Both arms initially retain the entire owned staging directory through a checked successful unload; verify each cache entry exists.
2. After unload, move A's **owned source directory** atomically to a private holding path on the same volume, leaving its original pathname absent. Keep B's directory at its original pathname. Both trees remain allocated, avoiding a disk-space benefit for A. Do not change framework URLs/options, daemon files, marker files or timestamps deliberately. The harness must transfer directory cleanup ownership safely; no leaked model handle or forgotten unload. Verify paths after releasing objects, then let the provisioning process exit. Abort if framework teardown removes B's tree.
3. At approximately 0, 1, 5 and 10 minutes after exit, construct fresh descriptors and use **only the already qualified `compiledModelExists` query**, with no source staging, load or compile. Check both original paths before/after each query; abort if probing materializes or changes them. The normal constructor cannot serve this purpose because its exclusive directory creation would conflict with B. Use test-only composition of established calls, not new selectors or a weakened production ownership guard. Record free-space trajectory and any ordinarily captured CacheDelete events; induce no pressure or maintenance.
4. If A reports absent, first restore its original owned directory by rename and query once more, without compilation. A return to “present” would show source-dependent availability rather than establish deletion of lowered artifacts. Then finish with at most two strict, zero-compile loads after recording the final query results and making both original paths available for the normal exclusive-staging loader. A miss stops that arm. Cleanup is limited to verified fixture-owned sources; leave daemon entries alone.

**Interpretation:** A repeatedly missing while B survives would support pathname-dependent retention, with compile order/graph identity still requiring a later reversed-order replication. Both disappearing around purge handling would favor shared maintenance/pressure and show that keeping sources is insufficient. Both surviving would be inconclusive, particularly if no maintenance occurred; do not escalate into disk filling or another 210-program campaign. A surviving while B disappears would argue against a simple missing-path rule.

This pair isolates pathname availability while keeping source bytes resident. Cache-query results establish availability through the API, not direct observation of protected lowered files. It cannot establish the daemon's actual `sourceURL`, prove a numeric quota, or rule out pressure-dependent eligibility. Until then, favor free-space headroom, one frozen graph set, bounded confirmed-miss recovery and a warm persistent owner over retaining an extra full-model source copy.
