# ANE attention experiment: kernel panic

**Current status:** after the approved single-input restart and subsequent
numerical corrections, shared-request tests passed for Gemma 4 12B sliding
attention at capacity 1024 and global attention at capacity 64. Only those two
geometries are now enabled in the research build. Multi-tensor calls and all
other attention geometries remain rejected before private API access. The
incident, initial containment and intermediate results below are chronological
evidence; they do not claim full-model decoding or sustained driver stability.

The private ANE attention experiment triggered a system panic and reboot. It is
not a working decoder backend. Further ANE hardware execution is paused while
the failure is investigated through source and artifact inspection.

## Source-level diagnosis and replacement

The upstream README at the exact previously consulted commit explicitly
documents a **single-input constraint** for the in-memory request interface:
multi-input requests fail, and inputs must be packed into one tensor. See
[maderix/ANE README, limitations](https://github.com/maderix/ANE/blob/d91c9845c0784dec7753048954fc6d0e8411fe29/README.md#limitations).
The four-input attention experiment violated that documented constraint.
This was overlooked during implementation. It is a concrete interface error;
it does not prove the internal cause of the driver's null-address fault.

The replacement in `ane_attention_layout.rs` generates one `[1,C,1,S]` input
and one output. Q, K, V and mask occupy explicit regions of that input;
reshape/transpose occur inside the MIL graph. The replacement runtime has its
own unconditional quarantine guard, so correcting the tensor count does not
silently re-enable execution. The lower-level multi-tensor guard remains too.

Host tests cover both Gemma 4 12B head layouts, cache coordinates, query/output
head order, 64-byte output-row alignment, and causal/sliding masks. They do not
prove MIL compilation, driver stability or ANE numerics. A child process is not
a safe containment boundary for validation because a driver panic reboots the
whole host. No hardware retry was made to diagnose this incident.

  `ane_attention::tests::hardware_attention_matches_imported_prefill_and_appended_decode`.

  The available evidence does not establish which case or framework operation

- The test process handle is no longer present, and its redirected `/tmp` log

- User-supplied panic excerpt SHA-256:
  `80d5de04d4cbca483a775b5ff672ae656d160f39ef3e1352a3c635971a4b0afc`.

The process identity and driver backtrace tie the reboot to this experiment.
They do not establish the underlying defect. Candidate boundaries include the
new multi-input request, tensor/surface layout, and the compiled dynamic-matmul
program. None is a confirmed root cause. Running in a child process cannot
contain a kernel-driver panic.

## Containment

`AneInMemoryKernel::compile_tensors` now rejects every multi-input or multi-output
program before loading the private framework or creating any IOSurface. There
is no environment-variable override. The attention hardware test is explicitly
marked quarantined, and a host-side regression checks that construction returns
the quarantine error. No ANE hardware test has been rerun after the reboot.

The previously tested single-input projection and fused FFN are separate,
partial results. They do not prove attention, full-model decode, KV handoff, or
end-to-end Gemma 4 12B disaggregation. Their `/tmp` measurement files were lost
in the reboot and must not be represented as durable checked-in receipts.

The full Metal-prefill / ANE-decode objective remains unfinished. Diagnosis and
host-side implementation can continue without retrying the known crashing path.

## Approved single-input validation, 2026-09-14 16:16 UTC

After the user explicitly approved one corrected attention test, an isolated
test executable was built with the reviewed guard change. The source guard
was restored to `false`, the normal test binary was rebuilt, and the host
quarantine test passed **before** the approved executable was run. A durable
run-intent record and exclusive per-phase journal were written under
`reports/gemma4-12b-evidence-20260914/ane-approved-attention-20260914T161346Z`.

The exact attention test passed once, without a retry. The journal records two
successful compile/load cycles, six completed evaluations and two unload
returns. PID 49104 executed the test. The Mac's boot time was unchanged.
The test executable's SHA-256 is
`edbddc86c5c65d2dbf9508876f865844f5e454932103d1fa837c8e5bce56b81f`.

The tested shapes were `(query heads, KV heads, head dimension)` of
`(16,8,256)` with physical capacity 32 and a three-token sliding mask, and
`(16,1,512)` with global capacity 64. Each imported five synthetic KV positions
and appended positions five, six and seven. All 36,864 compared output elements
were within the test's 0.003 absolute-error limit against the independent
FP32 attention calculation. This is a bounded passing result, not a measured
maximum error or a speed benchmark; the journal performs synchronous flushes.

The 1,024-token sliding shape, long-context ring wrap, full-model decode and
sustained stability remain unqualified. The source quarantine stays enabled.
This approved single-input result supersedes the earlier statement that no
post-panic ANE test had executed; the four-input path remains rejected.

## Subsequent numerical qualification and restricted enablement

The first full-window test failed a numerical assertion after two completed
single-input evaluations; the model unloaded and the Mac did not reboot.
Diagnostic softmax output localized the larger discrepancy to the value
reduction. Scaling probabilities by 32 before matmul and the result by 1/32
then passed the unchanged 0.003 absolute bound for all 86,016 checked output
elements. Two graphs created four independent requests and completed fourteen
evaluations, including physical wrap at the real 1024 sliding capacity and
filling global capacity 64. Both models unloaded; boot identity was unchanged.
The original program handle and one request could be dropped without changing
the other request's cache. Evidence is in
`gemma4-12b-evidence-20260914/ane-attention-scaled-probabilities-20260914/`.

Only `(16,8,256, sliding-1024)` and `(16,1,512, global-64)` are now enabled.
Other attention shapes and every multi-input/output request remain blocked
before private calls. This supersedes the earlier blanket attention quarantine
and the earlier statement that ring wrap was unqualified. Full-model decode,
longer global context and sustained stability are still separate acceptance
boundaries. The original four-input experiment has not been retried.

## Static FFN follow-up qualification

The same single-input/single-output sys guard and exact attention-geometry guard remain active. A complete 116-program static-FFN/dynamic-output decoder performed 208 successful evaluations and returned all 116 unloads without a boot change. Its imported caches, all 48 layer outputs and final top-five logits were byte-identical to the separately CPU-checked dynamic-FFN baseline. The successful-load cleanup now removes only the owned original source-weight file while retaining compiled `data` until final unload; five small static graphs/15 evaluations and one real 12B FFN/20 evaluations preceded the full-model run. The small-test initial intent understated an existing four-spatial-size loop; actual phase counts and the correction are preserved in `ane-source-weight-cleanup-components/result.json`.

Evidence: `gemma4-12b-evidence-20260914/disaggregated-static-ffn-capital-20260914/`. This further successful run does not erase the earlier multi-input driver panic or establish safety for unqualified geometries/interfaces. No multi-input experiment was retried.
